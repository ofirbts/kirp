# KIRP FOUNDATION MANIFESTO
Version 1.0

This document defines the stable base layer for all projects built under KIRP.

The purpose of this foundation is:
- Prevent chaos
- Prevent drift
- Prevent tool-dependency
- Enable intelligent AI collaboration
- Enable controlled growth
- Maintain cost-awareness
- Allow modular replacement of any component

This is not a tech stack.
This is an operating philosophy + structural protocol.

------------------------------------------------------------
SECTION 1 — CORE PRINCIPLES
------------------------------------------------------------

1. Clarity before action
2. Intent before execution
3. Scope before build
4. Plan before code
5. Replaceable components
6. Measured decisions
7. Iterative refinement
8. AI as assistant, not authority
9. Cost is a metric
10. Every project improves the system

------------------------------------------------------------
SECTION 2 — MINIMUM VIABLE FOUNDATION (MANDATORY)
------------------------------------------------------------

Every project must begin with these 4 documents:

1_PROJECT_INTENT.md
- Problem
- User
- Desired Outcome
- Success Metric

2_PROJECT_SCOPE.md
- In Scope
- Out of Scope
- Constraints
- Assumptions

3_EXECUTION_PLAN.md
- Phases
- Deliverables
- Dependencies
- Risks
- Validation points

4_AI_PROTOCOL.md
- AI role definition
- When AI can act
- When AI must ask
- Code modification rules
- Context limitation rules
- Cost-awareness rules

No project starts without these four.

------------------------------------------------------------
SECTION 3 — STRUCTURAL DISCIPLINE
------------------------------------------------------------

All projects must follow:

/project-root
  /docs
  /core
  /experiments
  /archive
  README.md

Rules:
- No random files in root
- Documentation separated from implementation
- Experiments isolated
- Deprecated code archived, not deleted

------------------------------------------------------------
SECTION 4 — AI COLLABORATION RULES
------------------------------------------------------------

1. AI must propose plan before code
2. AI must limit scope of changes
3. AI must never assume missing context
4. AI must explain tradeoffs
5. AI must recommend minimal viable solution first
6. AI must highlight cost implications
7. AI must provide diff-style changes when possible

------------------------------------------------------------
SECTION 5 — REPLACEABILITY PRINCIPLE
------------------------------------------------------------

Every external dependency must be:

- Configurable
- Isolated
- Replaceable

Examples:
- LLM provider
- Vector store
- Storage
- Backend framework
- UI framework
- Hosting provider

If replacing it requires rewriting the project — architecture failed.

------------------------------------------------------------
SECTION 6 — CONTROL LOOP
------------------------------------------------------------

Every project must include:

- Weekly review
- Cost review
- Architecture review
- Lessons learned section

Each project must produce:
- At least one reusable template
- At least one improvement to KIRP

------------------------------------------------------------
SECTION 7 — MATURITY LEVELS
------------------------------------------------------------

Level 1 — Structured
Intent + Scope + Plan exist

Level 2 — Controlled
Cost tracking + clear AI protocol

Level 3 — Modular
Replaceable components

Level 4 — Adaptive
System evolves with insights

------------------------------------------------------------
SECTION 8 — LUXURY LAYER (OPTIONAL, NOT MANDATORY)
------------------------------------------------------------

Only after stability:

- Automated testing
- Observability stack
- Multi-model routing
- Agent orchestration
- RAG pipelines
- Tool abstraction layer
- CI/CD automation

These are upgrades.
Not prerequisites.

------------------------------------------------------------
SECTION 9 — SUCCESS DEFINITION
------------------------------------------------------------

A project is healthy if:

- It can be explained clearly in 5 minutes
- It can be paused and resumed without confusion
- It does not depend on a single tool
- AI collaboration is controlled
- Costs are predictable
- Architecture can evolve safely
