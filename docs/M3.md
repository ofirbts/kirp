# M3 IdentityOS — Governed Module inside KIRP

M3 runs as a **tenant-scoped subsystem** within KIRP. Every M3 flow is an event flow; every state change is audited; no identity action bypasses governance.

## Architecture

- **Inbound:** M3 UI/API emit events (`m3.daily_reflection_submitted`, `m3.weekly_synthesis_requested`, etc.) → Event Registry → 9-stage pipeline.
- **Storage:** Event Store (Mongo), M3 Typed Memory (in-memory or Mongo), Qdrant (main collection with `module=m3` for semantic search), gap snapshots for KPIs.
- **Governance:** IdentityEntropyScore, OPA M3 resource types, WhatsApp escalation when score ≥ 0.6.

## API Routes (all under `/api/v1`)

| Method | Path | Description |
|--------|------|-------------|
| POST | `/m3/reflect` | Submit daily reflection → `m3.daily_reflection_submitted`. Optional header `Idempotency-Key`: duplicate returns 200 with same `event_id` (no double writeback). |
| POST | `/m3/synthesis` | Request weekly synthesis → `m3.weekly_synthesis_requested` |
| POST | `/m3/evolution` | Request monthly evolution → `m3.monthly_evolution_requested` |
| GET | `/m3/reflections` | List reflection entries (tenant/user scoped). Optional `?q=...` = semantic search; `?since=` and `?until=` (YYYY-MM-DD) = date range filter. |
| GET | `/m3/synthesis` | List weekly syntheses |
| GET | `/m3/evolution` | List monthly evolutions |
| GET | `/m3/actions` | List micro_actions (optional `?status=pending\|completed\|snoozed`) |
| GET | `/m3/kpis` | KPIs: Daily Reflection Completion, Recall Retention, Identity Alignment, Gap Closure (`?days=7`) |
| GET | `/m3/health` | Module status (event types, agents registered) |
| GET | `/m3/export` | Export reflections, actions, syntheses, evolutions as JSON (`?since=`, `?until=`) |

## Environment

See `.env.example` M3 section:

- `M3_ESCALATION_PHONE` — WhatsApp number for human approval when identity_entropy_score ≥ 0.6.
- `M3_ESCALATION_PHONE_<tenant>_<user>` — Per-tenant/user override.
- `M3_MEMORY_BACKEND=mongo` — Persist M3 data in MongoDB (collections: m3_reflections, m3_micro_actions, m3_weekly_synthesis, m3_monthly_evolution, m3_identity_profiles, m3_gap_snapshots, m3_idempotency). Requires `MONGO_URI`. Default: in-memory.

- `m3.daily_reflection_submitted`
- `m3.micro_action_generated` / `m3.micro_action_completed` / `m3.micro_action_snoozed`
- `m3.weekly_synthesis_requested` / `m3.weekly_synthesis_generated`
- `m3.monthly_evolution_requested` / `m3.monthly_evolution_updated`
- `m3.identity_vector_updated`
- `m3.gap_analysis_computed`
- `m3.human_governance_required`

## Pipeline Flow

1. Intent Declared → 2. Context Retrieval (M3 memory) → 3. Pattern Analysis → 4. Plan Generation → 5. Plan Critique (Discriminator) → 6. OPA → 7. Human Governance (WhatsApp if needed) → 8. Execution → 9. Reflection & Memory Writeback.

## Dashboard

- **Route:** `/m3` (Identity (M3) in sidebar)
- **Page:** `app/(dashboard)/m3/page.tsx` — submit daily reflection; date filter (All / Last 7 days / Last 30 days) and semantic search; KPIs; micro-actions; recent syntheses & evolution; back to list; pillar_scores and mood per reflection; Export button (downloads JSON).
- **API client:** `lib/apiClient.ts` — `m3Reflect`, `m3ListReflections` (q, since, until), `m3ListActions`, `m3ListSynthesis`, `m3ListEvolution`, `m3GetKpis`, `m3Health`, `m3SynthesisRequest`, `m3EvolutionRequest`, `m3Export`.

## Agents & classification

- **ReflectionClassifierAgent** (wired): classifies reflection text via LLM into `pillar_scores` (health, work, family, learning) and `mood`; result is persisted on the last reflection entry via `update_last_reflection_classification`.
- **GapAnalysisAgent** (Phase 2): LLM computes `gap_heatmap`, `pillar_deltas`, `top_gaps` from reflections and identity profile; stages call `append_gap_snapshot` so Gap Closure KPI and trend work.
- **MicroActionGeneratorAgent** (Phase 2): LLM suggests 1–3 micro-actions from context and gap result; stages persist them via `upsert_micro_action` (pending).

## Export

- **GET /m3/export?since=&until=** — JSON export of reflections, micro_actions, weekly_syntheses, monthly_evolutions (tenant/user scoped; optional date filter for reflections). Dashboard has an "Export" button that downloads the JSON.
